# 16 — Transferable Cognitive Infrastructure

Type: framework document (Gap 06)

## The Gap

Exceptional individuals' capabilities exist as personal talent. Scalability requires converting tacit expertise into explicit structures that others can adopt.

## Conversion Methodology

### From Person to Framework

Every individual studied is decomposed into:

| Layer | What It Captures | Example |
|---|---|---|
| Principles | Why their approach works | "Research-first eliminates superficial output" |
| Decision processes | How they choose between options | "If boundary is unmapped, expand before compressing" |
| Heuristics | Quick evaluation rules | "If drafting feels hard, research was skipped" |
| Workflows | Step-by-step execution sequences | The four-stage blog production workflow |
| Environmental conditions | When their approach succeeds | "Works when operator has domain familiarity" |
| Feedback loops | How they know it's working | "Original insight present = synthesis happened" |

### What Makes a Framework Transferable

A framework is transferable when:
1. **Named:** It has a canonical name in CE terminology (see TERMINOLOGY.md)
2. **Documented:** Principles, processes, and workflows are written down
3. **Testable:** There's a concrete way to verify the framework was applied correctly
4. **Independent:** It doesn't require the original individual's presence to execute
5. **Composable:** It can be combined with other frameworks for complex tasks

### Foundation to Factory Progression

| Phase | Description | Current State |
|---|---|---|
| Foundation | Core infrastructure built, departments designed | COMPLETE |
| Factory | Full pipeline operational, department by department | IN PROGRESS |
| Execution | Public-facing output, visible body of work | BEGINNING |

The transition from foundation to factory is the current phase. Each department build (Specs 07-09) is a factory component. Each published article is an execution output.

### CE as Transfer Mechanism

CE itself IS the transfer mechanism:
- Tacit expertise → CE governance documents (named, documented, testable)
- Personal workflows → CE skills and function folders (independent of any person)
- Individual judgment → CE verification checks and decision trees (composable)
- Personal knowledge → CE workspace artifacts (persistent, searchable, reusable)

### What This Means for Future Sessions

A first-contact CE agent reading these 16 artifacts should be able to:
1. Understand the business architecture without meeting the founder
2. Execute department workflows without prior training
3. Produce content that meets quality standards without personal guidance
4. Identify which department owns a task and what prerequisites it needs
5. Contribute to the archive by following documented patterns

If any of these five capabilities is missing, the cognitive infrastructure is not yet fully transferable. The gap closes by documenting what's still tacit.
