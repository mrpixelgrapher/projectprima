# 06 · Design

**Purpose:** compile the performance design into one file that planning and writing follow, and that next month's review reads.

## Contract

- **Reads:** `23-performance/01-results.md` to `05-tracking.md`.
- **Writes:** `23-performance/06-performance-design.md`.
- **Done when:** the file has the five sections below, each a compressed copy of its stage file's decisions, and (month route) a "changed from last month" list.

## Procedure

1. **Compress, don't re-decide.** Copy each stage's decisions in short form: the path table, the per-channel triggers and hooks, the tests, the tag scheme and report list.
2. **Rules for writing** (the part writers apply to every piece): the call to action per stage; the principles per stage with their true basis; the hooks to use first per channel; "never" rules (no false urgency, no unproved claims, no saturated angles).
3. **Month route:** list what changed from last month's design and why (the result that caused it).

## Output template

    # Performance design — <client> · <month>
    ## 1. Conversion path
    ## 2. Virality per channel
    ## 3. Tests this month
    ## 4. Tracking and the monthly report list
    ## 5. Rules for writing
    ## Changed from last month (month route)

## Worked example

*(illustrative)* Rules for writing: "Every Instagram carousel ends on the catalogue slide with the tagged bio link; covers use the price-in-headline hook (T1 winner); never 'limited stock' unless the client confirms a number."

## Traps
